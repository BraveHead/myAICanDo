M3 Context v1 数据流影响图

本图基于当前工作区改动，展示 Context v1 如何影响 AgentHarness 的 prompt 构建、工具调用结果、SSE 返回、日志记录和 filesystem sandbox 边界。核心变化是：大工具结果不再直接进入主上下文，而是写入当前线程 sandbox 的内部 artifact，并把轻量引用返回给模型与前端事件流。

阶段：M3 Context v1 日期：2026-07-15 范围：prompt layering + tool result offloading 不改变：tenant/user/thread 隔离与 LangChain createAgent

主数据流

主上下文与 prompt 流 工具调用执行流 offload 后的大结果流 按需读取 artifact 的回查路径

变更影响矩阵

数据环节
M3 前
M3 后
直接影响
Prompt

系统 prompt 输入

AgentDefinition.systemPrompt 和 memory/planning 文本偏拼接式组织，section 边界不够显式。

由 buildHarnessSystemPrompt() 按固定顺序输出 base、agent、memory、skills、tool-guidance。

模型接收的指令层次更稳定；memory 不再被拼到 agent prompt 尾部，planning/offload 规则统一进入工具指导层。

Tool

工具返回结果

工具成功返回后，原始 ToolMessage 直接进入模型上下文、SSE 结果和日志摘要流程。

wrapToolCall 先调用 offloadToolResultIfNeeded()，大结果写入 artifact，小结果继续 inline。

大文件读取和大搜索结果不会撑爆主上下文；前端仍收到完成事件，但 result 变成轻量引用。

Artifact

原始大结果保存

没有专门的 context artifact 保存层，原文主要停留在工具结果本身。

原始结果、摘要、参数、tool 元数据写入当前线程 sandbox 的 .context/offloads/*.json。

保留可追溯性，同时把模型主上下文压缩为 summary、artifactPath、originalSizeBytes。

Filesystem

文件系统边界

普通文件工具只面向用户可见目录，尚未区分内部 context artifact 写入口。

新增 writeInternalFilesystemArtifact()，仅允许 harness 写 .context/offloads/*.json；普通写/改/删仍限制在 workspace/** 和 notes/**。

内部上下文管理不污染用户文件操作审批；默认搜索和 glob 不扫描 .context，显式路径读取仍可用于复查。

Stream

SSE 与日志

tool_call.complete.result 可包含完整工具结果，日志摘要也可能面对更大的原始对象。

offload 的工具完成事件仍复用 tool_call.complete.result，其 result 只包含轻量 reference；工具完成后的 checkpoint 恢复重试会额外发送 agent_retry，说明重试原因。日志记录 artifact 路径、toolName、toolCallId、原始大小和摘要。

敏感或超长原文不会直接进入日志主体；页面能区分“工具成功完成”和“后续模型阶段失败并从 checkpoint 重试”。

边界不变项

隔离

tenant / user / thread

offload artifact 写在当前线程 sandbox 下，不改变现有租户、用户、线程隔离模型，也不改变 checkpointer 的 scope 输入。

Runtime

LangChain createAgent

M3 只在 harness 和 tool middleware 周边增强上下文管理，不替换 createAgent()，也不改变 agent definition 的组装职责。

Roadmap

skills / subagent

skills section 先保留为空位；不引入 M4 subagent，也不实现 M5 skills 扫描，避免把后续阶段提前混入 M3。
