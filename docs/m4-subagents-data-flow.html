M4 Subagents v1 数据流程图

本图描述当前改动后的 coordinator 委派链路：父 agent 通过 task 工具启动隔离的只读子 agent， 子 agent 复用现有 LangChain runner、LangGraph checkpointer 和 tenant/user/thread 隔离，只把 final report envelope 返回给父上下文。

阶段：M4 Subagents v1 入口：coordinator task UI：复用 tool_call 不新增数据库表 不开放子 agent mutation

主数据流

parent context only receives final report

顺序说明

顺序 节点 数据流动作 关键数据
1 用户发送复合任务 assistant-ui 发起一次 coordinator 对话请求。 threadId、agent=coordinator、用户消息。
2 Chat API API 校验租户访问，并解析当前 tenant/user/thread scope。 tenantHashId、userHashId、threadId。
3 Parent runner streamConfiguredAgentEvents() 创建父 agent 调用，并接入父线程 checkpoint。 父 agent 的 agentThreadId 与原始用户消息。
4 Harness 配置 createHarnessedAgent() 给 coordinator 注册 task，同时透传运行态。 apiKey、modelName、runConfig、runLogger。
5 Coordinator agent coordinator 根据 prompt 把复合任务拆给 task。 子任务目标和要选用的 subagent。
6 task 工具 校验白名单和上下文，生成子任务隔离 id。 subtaskId、childThreadId、task、context。
7 runSubagentTask() 启动子 agent runner，并消费子 agent 的内部事件流。 子 agent runConfig、child signal、final report accumulator。
8 只读子 agent 定义 按 agent 选择只读定义，确保子 agent 不拿 mutation tools。 filesystem、memory、weather 白名单定义。
9 Child LangChain agent 复用现有 runner 执行子任务，子线程独立 checkpoint。 threadId = childThreadId、runName=subagent:<agent>。
10 隔离存储与工具 子 agent 只调用只读工具，访问当前线程 sandbox、memory-store 或天气服务。 工具结果、LangGraph checkpoint、thread sandbox。
11 父 agent 汇总 runSubagentTask() 把子流压缩成 envelope，父 agent 把它当作 task 工具结果汇总。 ok、summary、toolResults、childThreadId。
12 前端展示 页面只展示父 agent 的 task tool_call 和最终回答。 SSE tool_call、text_delta、structured_response。

关键数据形态

输入到 task

  • agent：只能是 filesystem、memory、weather。
  • task：单个子任务指令。
  • context：可选补充上下文，不继承父上下文全文。

子任务隔离键

  • childThreadId = parentThreadId:subtask:subtaskId:agent
  • LangGraph 继续拼成 agent:tenant:user:childThreadId。
  • tenant/user/thread 三层隔离沿用原 runner。

返回给父 agent

  • ok、subtaskId、agent、childThreadId
  • summary 是父 agent 的主要依据。
  • toolResults 只保留摘要，不回填子 agent 全量消息。

能力边界矩阵

子 agent 允许工具 禁止工具 原因
filesystem 允许 list_filesystem_directory、read_filesystem_file、search_filesystem_text、glob_files 禁止 write_file、edit_file、delete_file 避免嵌套 approval，文件写改删仍只能由顶层 agent 触发现有确认流。
memory 允许 list_memories 禁止 save_memory、delete_memory 子 agent 只查询长期记忆，不修改 memory-store。
weather 允许 get_weather 无 mutation 工具 天气查询是无状态只读任务。

代码路径映射

父流程

  • src/app/api/tenants/[tenantId]/chat/route.ts：接收请求、解析 tenant/user/thread。
  • src/lib/agent/core/agent-runner.ts：创建 parent agent，收集 SSE 事件。
  • src/lib/agent/harness/agent-harness.ts：只给 coordinator 注册 task。
  • src/lib/agent/definitions/coordinator.ts：prompt 约束优先使用 task。

子流程

  • src/lib/agent/harness/subagents/task-tool.ts：校验参数、生成 childThreadId。
  • src/lib/agent/core/agent-runner.ts：runSubagentTask() 启动 child agent。
  • src/lib/agent/harness/subagents/readonly-definitions.ts：定义只读子 agent 工具集。
  • src/lib/tools/filesystem-tool.ts、src/lib/tools/memory-tool.ts：拆出 read-only tool factories。

事件与上下文边界

M4 v1 不新增 subagent_start 或 subagent_end SSE。 前端仍只展示父 agent 的 task 工具调用；子 agent 内部的工具调用由 runSubagentTask() 消费并压缩成摘要。 这保证主上下文不会被子 agent 的完整消息流和长工具结果污染，M7 Streaming v2 再扩展专门的 subagent 可视化事件。
